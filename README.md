# Agent Browser Bridge

## Installation

### 1. Install the extension

1. Download the latest zip from the [Releases page](https://github.com/lx223/agent-bridge-browser-extension/releases) and unzip it.
2. Open `chrome://extensions`, turn on **Developer mode**, click **Load unpacked**, and pick the unzipped folder.

A setup page opens. You can reopen it any time from the extension's toolbar icon.

### 2. Connect your agent

The setup page has one-click buttons for **Cursor** and **VS Code**. For other agents:

**Claude Code**

```bash
claude mcp add agent-browser-bridge -- npx -y agent-browser-bridge-mcp
```

**Claude Desktop and other agents**: add this to the agent's MCP config, then restart it.

```json
{
  "mcpServers": {
    "agent-browser-bridge": { "command": "npx", "args": ["-y", "agent-browser-bridge-mcp"] }
  }
}
```

The status on the setup page turns green when your agent is connected.

The toolbar icon shows the same status: a gray dot on the **A** means no agent is connected, and a green dot means an agent is connected.

## Multiple agent sessions

Several agent sessions can use the browser at the same time. The first MCP server process to start listens on port 17373 and holds the extension connection. Later processes connect to it on `ws://127.0.0.1:17373/relay` and forward their requests through it. If the hosting process exits, one of the remaining processes takes over the port and the extension reconnects to it automatically.

All sessions share one browser, so `undo_last_plan` undoes the most recent plan applied by any session.

## What your agent can do

**Tabs and windows** use Chrome's extension APIs: `list_windows`, `list_tabs`, `list_tab_groups`, `group_tabs`, `update_tab_group`, `ungroup_tabs`, `move_tabs`, `move_tab_group`, `close_tabs`, `apply_tab_plan`, `undo_last_plan`, `open_tab` and `navigate`.

**Page control** uses the Chrome DevTools Protocol through the extension's `debugger` permission:

| Tool | What it does |
|---|---|
| `snapshot_page` | Returns the page's accessibility tree. Elements carry refs such as `[ref=e42]`. |
| `click`, `hover` | Sends real mouse events to an element ref or to x/y coordinates. |
| `type_text`, `press_key` | Inserts text and sends real key events, e.g. `Enter` or `Control+a`. |
| `scroll` | Sends mouse-wheel events over an element or the viewport. |
| `screenshot` | Captures the viewport or the full page as PNG or JPEG. |
| `wait_for` | Waits for text to appear or disappear. |
| `evaluate` | Runs a JavaScript expression in the page. |
| `cdp_send` | Sends any raw DevTools Protocol command. |
| `detach_debugger` | Detaches from a tab and removes Chrome's debugging banner. |

A typical loop is `open_tab` or `navigate`, then `snapshot_page`, act on a ref, and snapshot again.

While a page tool is in use, Chrome shows a banner saying Agent Browser Bridge started debugging the browser. The extension detaches from a tab after five minutes without page commands, or when `detach_debugger` is called. Chrome does not let extensions debug `chrome://` pages, other extensions' pages, DevTools or the Chrome Web Store, so page tools fail there.

## Icons

Icon sources are generated by `packages/extension/scripts/render-icons.mjs`, which writes SVGs to `packages/extension/icons/` and renders PNGs into `packages/extension/public/icons/` with headless Chrome. Run `npm run icons -w agent-browser-bridge-extension` after changing the design. Set `CHROME_PATH` if Chrome is not at the default macOS location.
